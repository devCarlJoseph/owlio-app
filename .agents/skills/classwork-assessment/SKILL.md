# Classwork and Assessment

Use for creating, assigning, completing, submitting, reviewing, and evaluating learning activities. Keep each activity scoped to its classroom or other explicitly supported learning context.

## Activity types

The product plan distinguishes form-based work (quizzes, tests, exams, practice, review) from non-form work, including file/link submissions, projects and practical/offline activities, discussion-based activities, and reading/content completion. Form question types described include multiple choice/select, true/false, identification, short answer, and essay. Do not imply any type is implemented until verified.

## Workflow and records

Educators create and distribute work, set supported due dates and scoring rules, review submissions, provide grades/evaluations and feedback, and return work where supported. Students complete and submit work and view status/results released to them. The plan's possible lifecycle includes in-progress, submitted, under review, graded, and returned; align statuses to the actual contract rather than assuming this exact state machine.

Objective auto-grading may use educator-defined answer keys and points when supported. Written-response scoring can use rubrics or AI suggestions, but educators retain review and final decision authority. Keep official class records protected and separate from personal student tasks and study-space activity.

Use [AI assistance](../ai-assistant/SKILL.md) for generation/evaluation safeguards and [learner progress/reporting](../learner-progress-reporting/SKILL.md) for records and summaries. Never claim a submission, grade, or feedback was saved unless an API confirms it.
