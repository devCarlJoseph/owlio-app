# Capability status

Source review: 17 November 2026. Source and configuration establish implementation; browser reads and mocked tests establish different verification scopes.

## Operating mode

Auth/session and role guards always run. The compatibility export in `src/lib/api-mode.ts` is true; it no longer controls the guards or providers. There is no authentication preview bypass or local onboarding route. Original workspace layouts and browser-local tools are restored behind these guards.

`ApiWorkspaceContent` renders the original page adapters by default. Existing direct account links (`?source=account`) open the separate connected overview, student subjects/tasks/notes, notifications, schedule, and tutor sessions. Browser-local work is accessible in the original tools without automatic import. Built-in workspace demo collections have been cleared while preserving the UI: subjects, notes, tasks, Study Spaces/discovery/room occupants, room tasks/lockers, classwork, library resources, notification examples, calendar examples, and meeting layout participants/whiteboard seeds. Existing storage notices still identify unconnected features. Untouched legacy local seeds are hidden and backed up before the next normal save; edited seeds remain user work. This cleanup does not connect additional APIs. See [data cleanup and integration entry points](../DEMO_DATA_REMOVAL.md).

## Capability map

Migration 0052 and the matching API release enable owner-confirmed deletion of ended classrooms and student-only live meetings. Shared Study Spaces show a reusable meeting code for members. The student Meeting Room offers standalone create and join by code. Student calls also require the matching worker release and LiveKit configuration. See [classroom lifecycle](../CLASSROOM_API_INTEGRATION.md#end-and-delete-classrooms) and [meeting integration](../API_CONNECTION.md).

## Private classroom and locker files

The Materials tab, draft Classwork attachments, and account Study Space locker now have upload/view/download interfaces. Account lockers are private to their owner; device rooms and older device files remain local. The API adds resource-file endpoints and migration 0053, applied only to the explicitly approved local API database target. The corrected server key pair passed a live synthetic test through the actual R2Storage adapter, including byte validation, final write and signed inline view; both configured origins passed preflight and actual request Origin checks. Synthetic test objects were removed. Other environments still require migration reconciliation, API S3_* configuration, matching releases, and live application verification. See [R2 integration](../R2_FILE_INTEGRATION.md).
